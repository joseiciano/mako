# Story 7.11: Premium Scheduling Contracts & Persistence

**Milestone**: Milestone 7: Interviewer Verification & Premium Matching
**Description**: Complete the `booking_channel` contraction by re-backfilling gap rows, verifying zero nulls, and setting `NOT NULL` (requires Story 7.10 deployed and old Workers drained), then add the versioned Postgres persistence and shared contract foundation for the first-to-claim premium scheduling marketplace: the dedicated `premium_interviewer_slots` table, the durable claim-idempotency store (`premium_slot_claims`), the internal booking-credit-refund audit ledger (`premium_booking_credit_refunds`), and the current-user `isVerifiedInterviewer` projection. ### 2. Create the `premium_interviewer_slots` migration
- [ ] Create a versioned raw SQL migration in `packages/shared-backend/migrations/*.sql` using the workflow in `docs/system/system-design/db-schemas.md` (`pnpm db:migration:create -- premium_interviewer_slots`), placed after the migrations that establish the `"user"` table and the Better Auth schema.
- [ ] Create the physical `premium_interviewer_slots` table: `id UUID PRIMARY KEY`, `interviewer_id UUID NOT NULL REFERENCES "user"(id)`, `interview_type TEXT NOT NULL`, `start_time TIMESTAMPTZ NOT NULL`, `end_time TIMESTAMPTZ NOT NULL`, `status TEXT NOT NULL`, `created_at TIMESTAMPTZ NOT NULL`, `updated_at TIMESTAMPTZ NOT NULL`.
- [ ] Add a status CHECK constraint allowing exactly `available`, `claimed`, and `cancelled`.
- [ ] Add a `start_time < end_time` CHECK constraint and an exact-60-minute CHECK constraint `end_time = start_time + interval '60 minutes'` mirroring the `availability_slots` invariants documented in `docs/system/system-design/db-schemas.md`.
- [ ] Add an interview-type CHECK constraint allowing exactly the existing enum values `system_design`, `coding`, `behavioral` (preserve the existing type enum; do not introduce a new enum type).
- [ ] **No database defaults** for IDs, status, or timestamps. Writers generate the UUID with `crypto.randomUUID()` and supply `status`, `created_at`, and `updated_at` from trusted application code, per `packages/shared-backend/migrations/AGENTS.md`.
- [ ] Keep `interviewer_id` as a plain `REFERENCES "user"(id)` foreign key with no `ON DELETE CASCADE`, so interviewer account-retention/soft-deletion workflows do not silently drop published slots.
- [ ] Add a schema-readiness test asserting the table, all CHECK constraints, and the absence of database-generated ID/status/timestamp defaults.

### 5. Add the durable booking-credit-refund audit ledger
- [ ] Create a `premium_booking_credit_refunds` table in the same migration set, with **no database defaults** on any column:
  - `id UUID PRIMARY KEY` — app-generated with `crypto.randomUUID()` (never DB-defaulted).
  - `interview_id UUID NOT NULL UNIQUE REFERENCES interviews(id)` — one refund row per premium booking ever.
  - `scheduler_id UUID NOT NULL REFERENCES "user"(id)` — the scheduler who paid the credit being refunded.
  - `reason TEXT NOT NULL` with CHECK exactly one of `interviewer_cancelled | interviewer_account_deleted`.
  - `initiated_by_user_id UUID NOT NULL REFERENCES "user"(id)` — non-null (NOT NULL); the acting user is always recorded. The deletion workflow that produces `interviewer_account_deleted` supplies the cancelled interviewer's id, not null.
  - `credits_refunded INTEGER NOT NULL` with CHECK `credits_refunded = 1` — exactly one scheduler credit per refund.
  - `created_at TIMESTAMPTZ NOT NULL`.
- [ ] **Refund reasons are exactly `interviewer_cancelled` and `interviewer_account_deleted`.** There is no `admin_cancelled` or `system_cancelled` value, and no admin/system cancellation source exists anywhere in this milestone. Confirm no code path can write a refund row with any other reason.
- [ ] Add `idx_premium_booking_credit_refunds_scheduler ON premium_booking_credit_refunds (scheduler_id, created_at)` for scheduler refund-history listing.
- [ ] Add a schema-readiness test asserting the table, the unique `interview_id` constraint, the `reason` CHECK (only the two exact values), the `credits_refunded = 1` CHECK, the non-null `initiated_by_user_id`, and the scheduler-history index exist, and that the unique `interview_id` prevents a second refund row for the same interview.

This ledger is an **internal audit/idempotency ledger separate from `Credit_Transactions`** (the Stripe fulfillment ledger); document that distinction in `docs/system/system-design/db-schemas.md`.

## Implementation Notes
- **Prerequisites**: **Story 7.10 deployed and old Workers drained as a separate release** (required before the `NOT NULL` contraction in section 1; this contraction is its own PR/merge/deployment and is never combined with 7.10), the migration system and Better Auth schema from Milestone 1, the `"user".companies = true` eligibility flag from Story 7.8, and the Milestone 6 credit ledger/repository (`6-1`, `6-2`).
- `booking_channel` is a channel discriminator and is intentionally separate from `tier`. `tier` continues to encode the payment-policy label (`standard`/`premium`); it is not a channel value.
- **Implementation ownership points to later stories**: this ticket provides the typed, concurrency-safe persistence, shared contracts, and locked routes. Story 7.12 implements publish/list/cancel-slot endpoints; Story 7.13 the availability UI; Story 7.14 the cancellation/refund transaction (writing the `premium_booking_credit_refunds` ledger on interviewer cancellation/deletion); Story 7.15 the discovery/claim API (writing `premium_slot_claims` and the claim transaction); Story 7.16 the scheduler booking UI. Admin eligibility is owned by Story 7.8.
- The `interviews.booking_channel` CHECK permits `verified_interviewer`, but no production write path may create it until Story 7.15's claim transaction; `POST /api/interviews` remains AI-only.
- Standard matcher behavior and `POST /api/interviews` route semantics are unchanged; no `availability_requests`/`availability_slots` table is reused for premium slots.
- The `premium_booking_credit_refunds` ledger is written by Story 7.14's cancellation transaction, not by the migration. This ticket only creates the durable table, its indexes/constraints, contracts, and documentation. Reasons are exactly `interviewer_cancelled | interviewer_account_deleted`; there is no admin/system cancellation, so `admin_cancelled` and `system_cancelled` are not valid reasons.
- No interviewer charge, compensation, or payout fields/columns are added anywhere in this ticket or the milestone. Interviewers publish slots without any monetary consideration.

## End Goal
Postgres durably retains verified-interviewer 60-minute premium slots with exact invariants and query readiness, every `interviews` row carries a NOT NULL `booking_channel` (contracted after a clean deployed 7.10 and verified zero nulls), the current-user account exposes `isVerifiedInterviewer`, and premium claims and booking-credit refunds are deduplicated by durable ledger tables. The exact stable routes, schemas, pagination bounds, response envelopes, policy metadata, error shape, idempotency semantics, and source-of-truth system docs are locked here so later stories implement against a stable, documented surface.
